`SystemCatalogSource` owns the reusable metadata and snapshot on its actor. Bundle cache entries include the original/canonical identity, Info.plist and localization-resource stamps, and language preferences. Bundle directory timestamps/xattrs are excluded. A valid selected strings dictionary supplies the sole localized dependency; when it is absent or malformed, all potential Bundle fallback resources remain checked. Resource paths/listings are reused. A stamp check before and after reading avoids caching a known concurrent write. Successful scans prune absent bundles; incomplete scans do not replace cache state.

The source retains prepared search data when entries are equal. The controller independently compares complete entries before publishing, including targets, locations and icon references; fresh but equal snapshots from other loaders also remain silent. Watch changes still install monitoring and verify with a rescan. Settings metadata is retained in memory under its existing OS/language key. Watch diagnostics retain only aggregate counts/flags, and ignore callbacks from retired streams.

## Event trace and earlier attempts

The original M3 observation had 14 scans and 13 publications with no file-index updates. Directory mtimes alone could not explain it. The instrumented pre-cache observation lasted **64.003 seconds** with no events, scans or publications ([receipt](../../evidence/2026-11-18T191222Z-catalog/trace-before/receipt.json)). It kept the old scan/publication behavior while adding diagnostics and the retired-stream callback guard ([identity](../../evidence/2026-11-18T191222Z-catalog/trace-before/identity.json), [inputs](../../evidence/2026-11-18T191222Z-catalog/trace-before/source-manifest.json), [build](../../evidence/2026-11-18T191222Z-catalog/trace-before/build.log)). It is not evidence that the original burst was fixed.

The owned fixture does reproduce a plausible trigger: all three metadata-touch phases emit a directory-level event with flags `0x00000000`. The local SDK's `FSEvents.h` defines that flag as an unspecified directory change. Production still requests directory-level events; flags do not tell it that these were harmless xattr/timestamp updates, so the fix reconciles metadata rather than discarding those notifications.

Live traces also captured real activity: the first implementation saw one batch/two events, and the path-reuse revision saw two batches/four events. Each batch had one root-class event and one bundle-content event, with flags `0x00000000` and `0x00400000` (`ItemCloned`, per the same SDK header). Neither produced any publication or app metadata reread. This establishes which callback class triggered these new scans, **not which application/process caused them, nor that LaunchServices caused the original M3 burst**.

The first implementation still built Foundation URLs for every translation on each scan. Warm app scans took 49–102 ms, so it was not accepted as the performance result ([attempt 1](../../evidence/2026-11-18T191222Z-catalog/attempt-1/interpretation.json), [live trace](../../evidence/2026-11-18T191222Z-catalog/attempt-1/live/receipt.json)). Reusing POSIX paths lowered the short-run latest scans to 13–32 ms, but its latest event scan was 80.530 ms ([attempt 2](../../evidence/2026-11-18T191222Z-catalog/attempt-2/interpretation.json), [live trace](../../evidence/2026-11-18T191222Z-catalog/attempt-2/live/receipt.json)). The final implementation additionally narrows the common case to the selected localization. Earlier evidence and its build manifests remain preserved in the attempt directories.
