# Tight relative-path ranking

[UI section 13](../../build/ui-follow-up.md#13-path-queries-prefer-the-tightest-path) implements DEC-060: `apparate/build` prefers `apparate/build` over `apparate/docs/wiki/build` when the deeper folder has one or two opens; five opens can still raise it. [Search](../../features/search.md#tight-relative-paths) records the ranking rule and [file index](../../features/file-index.md) its compact-search integration.

## Implementation

Each ancestor skipped after the first matched parent segment costs 0.1, capped at 0.4 total. Interior gaps and gaps after the last match are included; ancestors above the first match are free. The existing 0.2 bonus for consecutive matched parent segments remains. Name tiers, kind ordering, usage formula, final depth tie-break and highlight construction are unchanged. The adjusted score participates in bounded selection, so the correct candidate can enter the top 50.

For a completed alignment, skipped ancestors equal `chain.count - firstMatchIndex - parentQueryCount`. Charging this capped amount when seeding the first dynamic-programming row makes the algorithm maximize the adjusted score, including cases where the old raw-score winner is looser than an alternative. Compact and regular search share `pathGapPenalty`; no extra alignment state or persistent cache is introduced. Its only callers are the existing parent-scoring paths. Non-path queries do no additional scoring work, and leading `/`, `~/` or `~` directory browsing keeps its existing behavior.
