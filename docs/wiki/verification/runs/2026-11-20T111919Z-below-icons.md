# Larger Below-layout icons

[UI follow-up section 11](../../build/ui-follow-up.md#11-larger-icons-in-the-below-layout) increases Below-layout icons to 32 points, centers them in the existing 40-point row and moves both text lines to x = 50. The [panel record](../../features/panel.md#below-layout-icon-size) and [verification recipe](../setup.md#below-layout-icon-checks) describe the implementation and checks. The requested memory comparison is now complete after the read-only catalog clarification. It misses the 40 MiB target and 47 MiB preferences comparison; the 60 MiB ceiling passes.

## Implementation

Below uses a 32 × 32-point icon at (9, 4), including command rows without a location. Title and location start at x = 50, with their previous vertical positions; hint geometry is unchanged. Inline and Right keep 20-point icons and x = 38 text. Row heights, panel heights, selection, accessibility geometry and hit testing retain their existing behavior.

File, app and setting artwork uses a 64-pixel raster for Below, versus 40 pixels for the compact layouts. Rasterization stays in the detached utility task; only PNG bytes cross executors, and each decoded image receives its matching point size. Symbols are size-specific vector images. Cache and pending-request keys include size. The cache keeps its existing `countLimit = 128`.

A layout size change immediately clears displayed row images and requests the new size, including while results are pending. Callback guards include the icon, item kind and size. A late old-size result can populate its own cache entry but cannot replace the current row image. A cold switch can temporarily omit the icon until the correct raster arrives; no smaller cached image is stretched to fill the larger frame. Warm switches can use both size variants without another load.
