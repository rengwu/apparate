# Indexed dot names

Section 6 / DEC-055 implements dot-named entries wherever configured roots and depths permit. Claude confirmed all five pushback details, including dot-app behavior, before implementation. **Functional checks passed; memory budgets have misses.** See the [guide](../../build/ui-follow-up.md), [file-index behavior](../../features/file-index.md), [search behavior](../../features/search.md) and [panel](../../features/panel.md).

## Behavior

Dot files and folders are retained as entries and obey `.gitignore`. Dot folders are terminal for an outer root; an explicitly configured dot root is traversed normally, with its own scope/depth. Its ordinary children remain eligible for ordinary queries. `node_modules`, links, packages, protected-folder gates and root overlap retain their existing rules. Terminal dot-entry events refresh their parent, while deeper events are filtered. Explicit roots separated from a recursive ancestor by a dot boundary get independent coverage. Rule-file edits still re-evaluate eligible subtrees. File-rule signature 5 rebuilds the cache; explicit saved folder lists are not migrated.

A leading dot in the parsed final name admits dot entries: `'.config`, `'.env`, `'Repo/.git`. Ordinary `config` skips them before matching; `Repo/` has an empty final name and excludes them. Default `.config` remains a Settings query. Compact chunks prepare ordinary/all kind buffers, and the regular index prepares basename eligibility. There is no per-query path construction or string-prefix check for each candidate. Storing and iterating extra entries still costs memory/time; the measurements do not claim zero cost.

Dot app bundles retain application kind and targets. Eligibility uses the original dot basename, which is also an alternate name when metadata supplies another display name. Matching app IDs from both sources still deduplicate. The existing direct-path listing, icons, highlights and action routes are retained. Finding home dot entries by name requires home or that folder to be within the configured roots.
