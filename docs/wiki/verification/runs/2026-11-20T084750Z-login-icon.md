# Login availability and app icon

[UI follow-up section 10](../../build/ui-follow-up.md#10-launch-at-login-and-the-app-icon) corrects the disabled Launch at login switch for a bundled app reporting `.notFound`, and pulls app-icon bundling forward from M7. The [Settings record](../../features/settings.md), [icon record](../../design/icon.md), [release plan](../../plan.md#m7-release-0-1-0) and [verification recipe](../setup.md#login-availability-and-app-icon) are updated.

## Changes

`NativeLoginService` maps `.notFound` and `.notRegistered` to the same off, enabled-switch state. The guide records Claude's independent observation that a never-registered ad-hoc bundle reports `.notFound` on this Mac; this run does not repeat a native service probe. Turning the switch on reaches the existing registration path, then Settings rereads the service state. A refusal retains the observed off state and shows its inline error. `.enabled` and `.requiresApproval` retain their behavior, including cancelling approval-pending registration. Only a run outside an identified `.app` bundle maps to unavailable. Future unrecognized service states fall back to not registered, allowing registration to report its actual outcome.

The fixture now carries a raw ServiceManagement status and uses the same pure mapping as the native adapter. It never constructs `SMAppService.mainApp` or registers/unregisters a real login item. The Settings verification starts at `.notFound`, drives the actual owned NSSwitch and checks state, enablement and the visible inline error.

Both `build.sh` and the fresh review assembly copy the existing `Resources/AppIcon.icns` into `Contents/Resources` and set `CFBundleIconFile` to `AppIcon`. The artwork is unchanged. No config or database migration is added.
